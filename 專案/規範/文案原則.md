# 文案原則

**每一段標題、副標、卡片文字都要通過這 3 條規則。**

參考 SOP 第 04 章。實作背後是 `market-copy` skill 的框架。

---

## 規則一 · 禁用字清單

以下這些「口號 / buzzword」全站不出現(grep 完必須是 0):

```
接地氣 · 可驗收 · 可治理 · 賦能 · 落地 · 數位轉型
慣性循環 · 產品思維 · Harness · 藍圖 · 生態 · 策略
心法 · 底層 · 頂層 · 轉型 · 顛覆 · 革命 · 智慧化 · 智能化
生產力 · 數據驅動 · 賦予 · 加值 · 聚焦 · 實場景
```

## 規則二 · 抽象要配情境

凡是描述「你可以做到什麼」的段落,底下要跟一個帶有:
- **人名**(王經理 / Evan / 業助 …)
- **時間點**(週一 7:30 / 週二早上 9:00 / 10:00:30)
- **具體數字**(1.5 小時 / 327 筆 / 30 秒 / 5 分鐘 / 半天縮到 5 分鐘)

的小故事。

## 規則三 · 不要辯護,只講正面

**負面錨定(絕對禁止)**:
- 「不是黑箱」→ 讀者根本沒指控,你反而把「黑箱」種進他腦中
- 「缺的不是 X,是 Y」→ 文青句構,要繞兩圈才聽懂

**改成**:
- 「AI 做了什麼,看得到」(正面)
- 「6 小時實戰,帶 3 條自動化流程回公司直接用 —— 週一自動寄週報、客戶 LINE 自動分流、大客戶斷單隔天就跳通知」(具體列舉)

## 對照範例(從 MFSD 專案實戰累積)

| 之前(口號) | 之後(白話) |
|---|---|
| 零容錯 ・ 可追溯 ・ 可治理 | 做錯一次客戶就跑 ・ 老闆問了答得出來 ・ 出包知道誰要修 |
| 20 年慣性循環 | 系統一堆,沒人用得起來 |
| 黑箱無法交代 | AI 出錯,沒人說得出為什麼 |
| AI 可控 / 流程可追溯 / 決策可驗收 | AI 做了什麼看得到 / 出包能倒帶查 / 不會「電腦說的」沒人扛 |
| 接地氣 | 講你公司的事 |
| 可驗收 | 不只會用,還能管 |
| 長期有效 | 工具改版也不用重學 |
| 視覺化操作 / 零程式門檻 | 不用寫程式 / 滑鼠拉一拉就能設計流程 |
| AX 成熟度模型 | 5 級學習地圖 |
| 學習成果 / 流程自動化能力 | 課完,你能做這些事 / 自己拉新的流程出來 |
| AI 應用能力 | 把 AI 接到你現在用的工具 |
| 可控 AI 系統 | 出包能倒帶看是哪一步壞了 |
| 企業導入藍圖 | 知道下一步該學什麼 |
| 通路績效 · 智慧客服 | 經銷商業績追蹤 · 客服訊息自動分類 |

**新專案適用時**:如果客戶素材裡有這種口號,不要照抄,自動翻成白話。翻不出來時停下來問使用者。
